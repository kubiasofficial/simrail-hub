# Community Discord relay

The public launcher sends its existing event envelope to this Cloudflare Worker. Device verification, idempotency, rate limits and delivery receipts are handled in `worker.mjs`. Secrets remain in Worker bindings; never copy them into the application or repository.

`discordCards.mjs` formats only validated events. Released clients keep their original schema and do not need an upgrade. Presentation revision: `compact-cards-2026-11-28`, exposed in the public `/health` response. Application version remains 0.8.5; existing release assets and tag are immutable.

New messages use a fixed SimRail Hub name/icon, state-specific colors, compact inline fields, readable elapsed time and a short community-evidence footer. Manual end locations and interrupted wall-clock records stay explicitly marked. Shift arrival still requires the user to confirm ending the shift. Approximate locations remain approximate; no Steam verification is implied. Names and values are escaped again for Discord markdown and all transformed output stays below embed limits.

This change affects future messages only. It does not edit message history or send an example to the live channel. `docs/verification/discord-cards-examples.json` contains sample payloads generated by the exact production formatter; the local HTML preview is only an approximation of Discord's column wrapping.

Validation: 268 tests across 43 files, including unchanged released-client events, duplicate receipts, all seven driving/shift event types, mentions/links, manual and uncertain locations, elapsed time, input limits and transformed embed limits. Live verification checks `/health` and unchanged hashes of all six 0.8.5 release assets, without posting a message.

Deployment uses the existing free Worker and D1 bindings:

```powershell
npx.cmd --yes wrangler@4.168.0 deploy --config community-relay/wrangler.jsonc --keep-vars --dry-run
npx.cmd --yes wrangler@4.168.0 deploy --config community-relay/wrangler.jsonc --keep-vars
node scripts/verify-discord-cards-deployment.mjs <deployed-worker-version-id>
```

No database migration or billing-plan change is required. Keep existing secrets and device credentials intact.
